# Домашняя работа №1 — Инфраструктура как код

Вариант 06 — Шрайнер.

## Параметры варианта

- Префикс ресурсов: `shrainer`
- Зона A: `ru-central1-d`
- Зона B: `ru-central1-b`
- Подсеть A: `10.16.1.0/24`
- Подсеть B: `10.16.2.0/24`
- Количество web-серверов: 3
- Порт nginx: `8018`
- Контрольное слово: `netlab`
- Окружение: `dev`
- Boot-диск: 25 ГБ
- Дополнительный диск web-сервера: 15 ГБ

## Архитектура

Стенд включает:

- одну виртуальную сеть;
- две подсети в разных зонах доступности;
- NAT-шлюз и таблицу маршрутизации;
- три web-сервера с nginx;
- дополнительный диск на каждом web-сервере;
- сервер приложения `shrainer-app` без публичного IP;
- target group;
- внешний Network Load Balancer;
- listener балансировщика `80 -> 8018`;
- HTTP health check на порту `8018`, путь `/`.

Web-серверы распределены между двумя подсетями.

Сервер приложения доступен по внутреннему IP из web-подсети и не имеет публичного IP.

## Файлы

- `create.sh` — создание стенда;
- `destroy.sh` — удаление стенда;
- `check.sh` — проверка работоспособности стенда;
- `cloud-init.tpl.yaml` — шаблон cloud-init.

## Создание стенда

```bash
./create.sh
```

По умолчанию создаются 3 web-сервера с дополнительными дисками по 15 ГБ.

Поддерживаемые параметры:

```bash
./create.sh --web-count 3 --disk-size 15
```

Также можно переопределить:

```bash
./create.sh \
  --web-count 3 \
  --disk-size 15 \
  --port 8018 \
  --word netlab \
  --prefix shrainer \
  --zone-a ru-central1-d \
  --zone-b ru-central1-b
```

Повторный запуск `create.sh` не должен создавать дубликаты уже существующих основных ресурсов.

## Проверка стенда

```bash
./check.sh
echo $?
```

Скрипт проверяет:

1. доступность web-серверов через балансировщик;
2. получение ответов от всех трёх web-серверов;
3. доступность сервера приложения по внутреннему IP с web-сервера.

При успешной проверке:

```text
Код возврата: 0
```

При ошибке:

```text
Код возврата: 1
```

Если `check.sh` завершился с ошибкой, необходимо проверить:

- состояние виртуальных машин;
- состояние nginx;
- состояние target group;
- health checks балансировщика;
- сетевую доступность ресурсов.

После устранения причины необходимо повторно выполнить:

```bash
./check.sh
```

## Удаление стенда

```bash
./destroy.sh
```

Скрипт удаляет созданные ресурсы, включая балансировщик, target group, web-серверы, сервер приложения, дополнительные диски, подсети, таблицу маршрутизации, NAT-шлюз и сеть.

Повторный запуск `destroy.sh` безопасно пропускает уже отсутствующие ресурсы.

## Метки ресурсов

Ресурсы, создаваемые скриптом напрямую, получают метки:

- `owner=shrainer`
- `env=dev`

Скрипт `destroy.sh` ищет ресурсы по меткам `owner` и `env`, а не по заранее известным именам. Это позволяет удалять ресурсы нужного владельца и окружения независимо от их конкретных имён.

Исключение составляют загрузочные диски виртуальных машин, создаваемые вместе с ВМ через `--create-boot-disk`: они не получают заданные скриптом метки. Загрузочные диски имеют параметр `auto_delete` и удаляются автоматически вместе с виртуальными машинами.

Дополнительные диски web-серверов создаются отдельно, поэтому получают метки и находятся `destroy.sh` по ним.
