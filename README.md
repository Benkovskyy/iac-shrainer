# iac-shrainer

Учебный репозиторий по дисциплине «Инфраструктура как код».

В репозитории находятся практические и самостоятельные работы по развёртыванию инфраструктуры в Yandex Cloud и её автоматизации.

## Структура репозитория

### work-01

Практическая работа № 1.

Содержит:
- create.sh — создание инфраструктуры;
- destroy.sh — удаление созданных ресурсов;
- commands.sh — журнал использованных команд;
- notes.md — заметки по выполнению работы.

Префикс ресурсов: shrainer-06.

### work-02

Практическая работа № 2.

Содержит:
- create.sh — автоматизированное создание стенда;
- destroy.sh — удаление ресурсов стенда;
- cloud-init.tpl.yaml — шаблон cloud-init.

Параметры варианта:
- префикс: shrainer-06;
- слово: netlab.

Создание стенда:

    bash work-02/create.sh

Удаление стенда:

    bash work-02/destroy.sh

### hw-01

Самостоятельная часть работы по автоматизации инфраструктуры.

Содержит:
- create.sh — создание стенда;
- destroy.sh — удаление стенда;
- check.sh — проверка работоспособности;
- cloud-init.tpl.yaml — шаблон cloud-init;
- расхождения.md — журнал обнаруженных расхождений.

## Практическая работа № 4

Тема: «Стенд в манифесте Terraform».

В рамках работы реализовано декларативное управление облачной инфраструктурой Yandex Cloud с использованием Terraform.

### Структура work-04

- `versions.tf` — настройка провайдера Yandex Cloud и ограничение его версии;
- `main.tf` — описание сети, подсети, виртуальной машины и дополнительного диска;
- `cloud-init.tpl.yaml` — первоначальная настройка Ubuntu и nginx;
- `.terraform.lock.hcl` — фиксация версии провайдера и контрольных сумм.

### Параметры варианта 06

- Префикс ресурсов: `shrainer-06`;
- Зона: `ru-central1-d`;
- Подсеть: `10.16.1.0/24`;
- Операционная система: Ubuntu 22.04 LTS;
- Порт приложения: `8018`;
- Загрузочный диск: 25 ГБ;
- Дополнительный диск: 15 ГБ;
- Оперативная память: 4 ГБ;
- Окружение: `dev`;
- Слово на веб-странице: `netlab`.

### Выполненные задачи

1. Созданы виртуальная сеть, подсеть и виртуальная машина с помощью Terraform.
2. Настроен nginx через cloud-init.
3. Добавлена метка `owner = "shrainer-06"` без пересоздания виртуальной машины.
4. Добавлен параметр `hostname = "shrainer-06-tf-app"`, потребовавший пересоздания виртуальной машины.
5. Создан дополнительный диск размером 15 ГБ и подключён через `secondary_disk`.
6. Оперативная память увеличена с 2 до 4 ГБ.
7. Добавлен параметр `allow_stopping_for_update = true`, разрешающий временную остановку виртуальной машины при изменении её параметров.
8. Проверены конфигурация Terraform, доступность nginx, подключённые диски и объём оперативной памяти.

### Управление инфраструктурой

Рабочий каталог: `work-04`.

Основные команды:

- `terraform init` — инициализация проекта;
- `terraform fmt` — форматирование конфигурации;
- `terraform validate` — проверка корректности;
- `terraform plan` — предварительный просмотр изменений;
- `terraform apply` — применение конфигурации;
- `terraform output -raw app_ip` — получение публичного IP-адреса;
- `terraform destroy` — удаление созданного стенда.

### Результаты

Terraform позволяет управлять инфраструктурой декларативно, автоматически определяя зависимости между ресурсами и необходимые действия при изменении конфигурации.

Установлено, что изменение меток и подключение дополнительного диска выполняются без пересоздания виртуальной машины. Изменение `hostname` требует её пересоздания, а увеличение оперативной памяти — временной остановки с явным разрешением.

Настройка nginx проверена HTTP-запросом. Сервер возвращает:

`netlab on shrainer-06-tf-app`

### GitLab

Основная часть работы выполнялась в ветке `terraform-stend`, самостоятельная часть — в `terraform-resursy`.

Изменения отправляются в основную ветку `main` через Merge Request после успешного прохождения проверок.

Файлы состояния Terraform (`*.tfstate`, `*.tfstate.*`), локальные плагины (`.terraform/`) и секретные ключи исключены из репозитория. Файл `.terraform.lock.hcl` сохраняется в Git.
