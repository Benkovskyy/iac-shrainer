# iac-shrainer

Учебный репозиторий по дисциплине «Инфраструктура как код».

Проект посвящён созданию, настройке и автоматизации облачной инфраструктуры Yandex Cloud с использованием Bash, cloud-init, GitLab CI/CD и Terraform.

| Параметр | Значение |
|---|---|
| Вариант | `06` |

| Зона доступности | `ru-central1-d` |

## Практические работы

### Практическая работа № 1 — work-01

Тема: Создание облачной инфраструктуры с использованием Yandex Cloud CLI и Bash.

Выполненные задачи:
- Создание облачных ресурсов через Yandex Cloud CLI.
- Автоматизация развёртывания инфраструктуры с помощью Bash.
- Проверка созданных ресурсов и их доступности.
- Автоматизация удаления инфраструктуры.

Основные файлы:
- `create.sh` — создание инфраструктуры.
- `destroy.sh` — удаление ресурсов.
- `commands.sh` — журнал выполненных команд.
- `notes.md` — заметки по выполнению работы.

### Практическая работа № 2 — work-02

Тема: Автоматизированное развёртывание виртуальной машины с использованием cloud-init.

Выполненные задачи:
- Автоматизация создания виртуальной машины в Yandex Cloud.
- Первоначальная настройка операционной системы через cloud-init.
- Установка и настройка веб-сервера nginx.
- Проверка доступности веб-приложения.
- Автоматизация удаления облачных ресурсов.

Основные файлы:
- `create.sh` — создание и настройка стенда.
- `destroy.sh` — удаление инфраструктуры.
- `cloud-init.tpl.yaml` — шаблон первоначальной настройки виртуальной машины.

### Практическая работа № 4 — work-04

Тема: Создание и управление облачной инфраструктурой с использованием Terraform.

Выполненные задачи:
- Создание декларативной конфигурации облачной инфраструктуры.
- Развёртывание виртуальной машины с веб-сервером nginx.
- Добавление меток ресурсов без пересоздания виртуальной машины.

- Увеличение оперативной памяти виртуальной машины с 2 до 4 ГБ.

### Практическая работа № 5 — work-05

Тема: Параметризация Terraform с использованием variables, locals, outputs, for_each, moved и dynamic.

Выполненные задачи:
- Вынос параметров инфраструктуры в переменные Terraform.
- Добавление проверки допустимого диапазона порта приложения.
- Передача пароля через чувствительную переменную `web_password`.
- Исключение секретных данных из системы контроля версий.
- Использование `locals` для формирования имён ресурсов и общих меток.
- Использование `outputs` для получения адресов виртуальных машин.
- Создание группы из трёх виртуальных машин с помощью `for_each`.
- Перенос адреса существующей виртуальной машины с помощью `moved` без её пересоздания.
- Настройка HTTP Basic Authentication для nginx.
- Создание группы безопасности с динамическими правилами `ingress`.
- Настройка входящих TCP-портов `22` и `8018`, а также исходящего трафика.
- Проверка управления сетевым доступом через список разрешённых портов.
- Удаление созданной инфраструктуры с помощью Terraform.

Основные файлы:
- `versions.tf` — настройка Terraform и провайдера Yandex Cloud.
- `main.tf` — описание сети, подсети и виртуальных машин.
- `variables.tf` — объявления и проверки переменных.
- `terraform.tfvars` — значения параметров варианта.
- `locals.tf` — локальные значения и общие метки.
- `outputs.tf` — выходные значения инфраструктуры.
- `security.tf` — конфигурация группы безопасности.
- `cloud-init.tpl.yaml` — шаблон настройки nginx и авторизации.
- `.terraform.lock.hcl` — фиксация версий провайдеров.

## Основные команды

### Bash

Создание инфраструктуры:

`bash work-02/create.sh`

Удаление инфраструктуры:

`bash work-02/destroy.sh`

### Terraform

Команды выполняются из каталога соответствующей практической работы.

| Команда | Назначение |
|---|---|
| `terraform init` | Инициализация рабочего каталога |
| `terraform fmt` | Форматирование конфигурации |
| `terraform validate` | Проверка корректности конфигурации |
| `terraform plan` | Просмотр планируемых изменений |
| `terraform apply` | Создание и изменение ресурсов |
| `terraform output` | Просмотр выходных значений |
| `terraform state list` | Просмотр ресурсов в состоянии Terraform |
| `terraform destroy` | Удаление инфраструктуры |

## Безопасность

Для управления конфиденциальными данными используются переменные GitLab CI/CD, чувствительные переменные Terraform и правила `.gitignore`.

Из системы контроля версий исключены:
- Файлы с секретными значениями `*.auto.tfvars`.
- Файлы состояния `*.tfstate` и `*.tfstate.*`.
- Рабочий каталог `.terraform/`.
- Закрытые SSH-ключи и ключи сервисных аккаунтов.

Параметр `sensitive = true` скрывает значения в стандартном выводе Terraform, однако не шифрует данные в файле состояния.
